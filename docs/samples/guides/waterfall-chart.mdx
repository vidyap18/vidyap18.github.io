# Waterfall

<span className="vp-label">Real page from a user guide I own. Product name, people and other identifying details are masked.</span>

A waterfall chart shows how an initial value increases or decreases through a series of intermediate steps to reach a final total. Each bar is a positive or negative contribution, so you can read cumulative effects across a sequence such as revenue build-up, budget variance, or profit breakdown across regions.

## When to use a waterfall

<DecisionTree question="Are you showing gains and losses that build to a final total?">
  <DecisionYes title="Use a Waterfall">{`
- Each step adds or subtracts from a running total, building toward a final number
- The order of steps matters: opening value, then changes, then closing value
- Shows what's contributing to each increase or decrease, not just the total
  `}</DecisionYes>
  <DecisionNo title="Use one of these instead">
    <DecisionLink label="Bar chart">for comparing independent categories with no running total</DecisionLink>
    <DecisionLink label="Pie">or **stacked bar** for part-to-whole at one moment</DecisionLink>
    <DecisionLink label="Line chart">for a continuous trend over time</DecisionLink>
  </DecisionNo>
</DecisionTree>

## What you need before starting

A waterfall needs at least a category column and a value column. A third column is optional and unlocks stacking.

| Column | Requirement | Description |
| --- | --- | --- |
| **Categories** | <span className="doc-required">Required</span> | The step labels along the x-axis (Example: Opening Balance, monthly changes, Closing) |
| **Value** | <span className="doc-required">Required</span> | The numeric amount for each step (Example: Sales, Revenue, or Cost) |
| **Stack by** | <span className="doc-optional">Optional</span> | A sub-category that breaks each bar into segments (Example: Product Type) |

:::info
**Delta or cumulative?** A step's **Value** can be a delta (a change) or a cumulative total. Confirm which your data uses before building, so the bridge reflects what you expect.
:::

:::tip
**Quick build:** add a chart widget, choose **Waterfall**, pick your **Categories**, then pick your **Value** (and optionally add **Stack by**). Everything under [Configuring chart properties](#configuring-chart-properties) is refinement.
:::

***

## How values are calculated

The waterfall chart determines each step's role automatically based on the order of your data. 

The first row becomes the **Start** value, the rows that follow become Deltas (increases or decreases), and the **Total** bar is added at the end with no extra setup. If you need a checkpoint partway through, insert a **Subtotal** from the **Styles** tab.

## Configuring chart properties

When creating or editing a Waterfall chart, the right panel shows three tabs: **Data**, **Options**, and **Styles**. Each row below matches an accordion in that panel; click to expand.

To control what data is displayed, see Filter Settings.

<TabsContent value="data">

Look for the hide icon next to a measure or attribute.

* **Hidden measure:** remains in the query and continues to participate in tooltips, drilldown, and other calculations that depend on it. Hiding it changes only the display, not the underlying data.
* **Hidden attribute:** removes it from the chart. It does not continue to participate in tooltips, drilldown, or other calculations.

<details>
<summary><strong>Categories</strong> <span className="text-muted-foreground">step labels along the x-axis</span></summary>

Click **+ Add Attribute** and select the column representing your steps.

**Example:** Opening Balance, Jan Sales, Closing.

</details>

<details>
<summary><strong>Value</strong> <span className="text-muted-foreground">numeric measure that determines bar height</span></summary>

Click **+ Add Measure** and select the column. Each step can be a delta (change) or a cumulative total; the first step is read as the Start value.

**Example:** Sales, Revenue.

</details>

<details>
<summary><strong>Stack by</strong> <span className="text-muted-foreground"><span className="doc-optional">Optional</span> · Break each bar into sub-segments</span></summary>

Click **+ Add Attribute** and select the column. When assigned, the API returns flat rows with the fields `step`, `stackBy`, and `value`. Connectors are off by default while the chart is stacked.

**Example:** Division, Product Type.

</details>

<details>
<summary><strong>Split By</strong> <span className="text-muted-foreground"><span className="doc-optional">Optional</span> · Divide into side-by-side panels</span></summary>

Click **+ Add Attribute** and select the column to split by. Each unique value generates a separate chart panel side by side. To arrange the panels, use **Styles > Split by**.

**Example:** Region, Scenario.

</details>

<details>
<summary><strong>Row Limit</strong> <span className="text-muted-foreground">Maximum rows displayed · default 1000</span></summary>

Enter a number or use the arrows to set the limit. Lower it if the chart is slow with large datasets.

</details>

</TabsContent>
<TabsContent value="options">

<details>
<summary><strong>Scenario comparison</strong> <span className="text-muted-foreground">compare the same steps across scenarios</span></summary>

Use the **Enable Scenario Comparison** toggle (on by default) to display and compare multiple scenarios side by side across the same waterfall steps.

**Example:** Plan vs. Actual.

</details>

<details>
<summary><strong>Sort by</strong> <span className="text-muted-foreground">order steps by a measure</span></summary>

1. Click the pencil icon next to **Sort by**.
2. Select the column and choose the order. The order labels match the column type (for example, **A → Z** / **Z → A** for text and **1 → 9** / **9 → 1** for numbers).
3. Click **+ Add sort option** for multiple rules.

Rules apply as you change them. Drag the handle to reorder rules; use the delete icon to remove one.

You can sort by **Categories**, which sets the step order, or by **Value**, which reorders steps by magnitude. **Stack by** is not sortable.

</details>

</TabsContent>
