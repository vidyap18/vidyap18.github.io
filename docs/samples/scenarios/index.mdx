# User guide sample: scenarios and permissions

<span className="vp-label">Real page from a user guide I own. Product name, people and other identifying details are masked.</span>

Three real pages from a user guide I own, with their four interactive "try it" demos. The product name, people, organisations, links into the rest of the documentation and the product video are masked, and every screenshot was reviewed and masked where it showed anything identifying. The writing, structure and demos are otherwise as published.

- `scenario-permissions.md`: what each permission allows, how access is decided across three levels, an access calculator you can use, and what to do when an action is blocked.
- `syncing-and-committing-scenarios.md`: choosing between sync and commit, a simulator that shows what each operation overwrites, the record-level trap, cascading changes.
- `getting-started-with-scenarios.md`: a task page with a create-a-scenario walkthrough.
- `demos/`: the four demos, plain HTML, CSS and JavaScript.

Process note: scenario access combines three levels and two rules, which is accurate in a table but slow to apply to one person's case. Instead of asking readers to work through a matrix, the page lets them calculate their own case: three selections, one answer, and the rule that produced it. The simulator does the same for sync and commit, where the costly mistake is overwriting a colleague's work. Next: instrument the demos to see which combinations readers try most.
