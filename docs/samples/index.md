# Writing samples

My employer's documentation is behind a login. The user guides are real pages I own, with the product name, people and other identifying details masked. The API documentation is an original set written for a fictional product.

## User guides

Real pages, masked. The scenario guides carry four try-it demos readers can use before they touch real data.

- [Getting started with Scenarios](/samples/scenarios/getting-started-with-scenarios): a task page with a create-a-scenario walkthrough.
- [Understanding Scenario Permissions](/samples/scenarios/scenario-permissions): what each permission allows, and an access calculator.
- [Syncing and Committing Scenarios](/samples/scenarios/syncing-and-committing-scenarios): choosing between sync and commit, with a simulator that shows what each operation overwrites.
- [From draft note to released note](/samples/guides/gray-note-to-green-note): how a custom analytics note moves from an editable draft to a frozen, released version.
- [Waterfall chart](/samples/guides/waterfall-chart): a reference page that opens with a decision tree and includes a live chart.

## Release notes

- [Interactive release notes](/writing/release-notes): one real release in the layout it was published in, with highlights, filters, expandable entries and a live preview.

## API documentation

A fictional API with non-runnable examples, written against an OpenAPI 3.0 spec.

- [Your first query in 10 minutes](/samples/api/tutorial-first-query): a tutorial.
- [Query rows](/samples/api/reference-query-endpoint): an endpoint reference.
- [OpenAPI spec](/samples/api/spec): the single source of truth for every field.
