# Writing samples

My employer's documentation is behind a login. Set 1 is real pages I own, with the product name, people and other identifying details masked. The other sets are original re-creations for a fictional company, Meridian, that keep the structure and decisions of the real work. Each set opens with a short note on who it is for and why it is built the way it is.

| Set | What it shows |
| --- | --- |
| [User guide: scenarios and permissions](./scenarios/index.mdx) | Real pages, masked, with four try-it demos: an access calculator, a sync and commit simulator, a cascade stepper and a walkthrough. |
| [User guide: train your first forecast model](./forecast/index.mdx) | Re-created. A nine-step quick start, a retrain how-to, a settings reference and a page on the in-product AI assistant. |
| [Release communication](./release-comms/index.mdx) | Re-created. A release note, the customer briefing and email behind it, an internal briefing and a video brief. |
| [API documentation](./api/index.mdx) | Re-created, not runnable. A tutorial, a how-to, a reference page and an explanation, written against an OpenAPI 3.0 spec. |
| [Writing documentation an AI assistant can answer from](./method/retrieval-ready-docs.mdx) | A method article. |
| [Per-note documentation versioning](./design/per-note-doc-versioning-proposal.mdx) | Re-created. A design proposal to engineering. |
