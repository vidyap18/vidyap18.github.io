# Deciding what to document next from the data

<span className="vp-eyebrow">Measurement · 2026</span>

![Screenshot borders audit brief](/img/work/image-audit-brief.png)

**Ticket analysis.** Of 222 support tickets between 1 September and 9 October 2026, about half were knowledge gaps: questions the documentation should have answered. That set the next plan: about 40 short how-to videos aimed at the most frequent gaps.

**Dashboards.** Prototype dashboards for leadership, customer success and the docs team, shared in October 2026: documentation usage, search behaviour, and assistant questions per account, refreshed from the analytics source on demand. The assistant review view, from September 2026, lists questions to review alongside usage.

> "That's exactly what I wanted to see and correlate ticket volume with." Customer Success Business Partner, EMEA

**Search analytics.** I instrumented the docs search bar so every search, and every search that finds nothing, is recorded.

**Screenshot audit.** 1,017 of the 2,435 screenshots on the docs site (42%) had no border, because borders were added by hand when the screenshot was taken. I proposed one CSS rule that draws the border on every page, with before-and-after previews. Status: proposal.

## What this shows

Using data to pick what to write next, and saying plainly what is a prototype and what is a proposal.
