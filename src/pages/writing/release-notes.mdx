<ReleaseCard id="rn-inspect" category="General" tag="New Feature" title="Meet Inspect: The Pre-Flight Check for Your Sequence and Data" teaser="Check your Sequence and Data for configuration issues before you run or deploy, with every finding graded by severity.">

You deploy, and a chart comes back empty. Somewhere upstream a table was deleted, a mandatory column never got mapped, or a Note was never run. The app was always going to break. You just found out at the worst possible moment.

<L>Inspect</L> moves that discovery earlier. Run it whenever you like, and it tells you what is wrong, how bad it is, and who fixes it.

**What's New**

* **One button, two places**: Inspect sits in the bottom panel of every Sequence, and in Data. Click **Inspect** &gt; **Run now** and it checks your Notes, data maps, and executions.
* **Findings graded by severity**: **Critical** means something your Application depends on no longer works. **Warning** means something is incomplete but still runs.
* **Every finding says who fixes it**: **Fix in sequence** means it is yours to correct. **Needs Meridian Support** means it is ours, so raise a ticket and move on.
* **Detail when you want it**: **Show technical details** opens the underlying JSON. **Download Report** gives you a .txt file naming each finding and the table it sits on, which beats reading logs.

<ReleaseClip src="/img/release/inspect.mp4" alt="Running Inspect from the bottom bar of a Sequence" />

Want the steps? The <L>Inspect</L> guide walks through both flows.

</ReleaseCard>

<ReleaseCard id="rn-freshness" category="General" tag="New Feature" title="Sequence Freshness: Spot the Stale Notes Before Anyone Else Does" teaser="See which Notes in a Sequence are current and which are behind, and re-run the stale ones from a single panel.">

An upstream Note reruns with new data. Somewhere downstream, a few Notes are still working from the old run, and nothing on the canvas tells you which ones. Until now, the only way to find out was to open Notes one at a time.

**What's New**

* **Freshness for the whole Sequence**: Click the **Show Sequence Freshness** icon in the canvas toolbar. A panel opens showing how much of the Sequence is current, then lists every Note that needs attention.
* **Four statuses**: **Current** means the Note reflects the latest upstream data. **Behind** means an upstream Note has newer data than this Note last ran with. **Updating** means the Note is pending or running. **Review** means it failed, was cancelled, hit an upstream failure, or has never run.
* **A reason for every flag**: Each Note in the list says why it needs attention, for example, "Optimize Routes has a newer run." When more than one issue applies, the most relevant one shows first, with a count of the rest.
* **Re-run right from the panel**: Click **Re-run** next to a Note to bring it up to date, or click its name to jump to it on the canvas.

<ReleaseCard id="rn-dev-prod" category="Next-Gen Applications" tag="New Feature" title="Build in Development, Deploy to Production" teaser="Creators can build and test changes in Development, then deploy a stable version for Consumers when it is ready.">

Until now, every change a Creator saved to an Application went live instantly, in front of everyone using it. Next-Gen Applications now have separate **Development** and **Production** versions, so you can build in one and keep the other steady.

<div className="rn-embed"><iframe src="https://fast.wistia.net/embed/iframe/nh4bb7rchx" title="Development and Production walkthrough" allow="autoplay; fullscreen" loading="lazy" allowFullScreen></iframe></div>

**What happens to your existing Applications**

Every existing Application in Next-Gen mode automatically becomes its **Development** version. Its URL, Scenarios, data, and user access remain unchanged, so your team can continue using it as it does today.

An Application is not automatically deployed to Production. You decide which Applications to deploy and when, and there is no need to move everything at once.

<ReleaseClip src="/img/release/dev-prod-dropdown.mp4" alt="The version dropdown in the Canvas Toolbar, showing Development and Production" />

**Development and Production**

| Development | Production |
| --- | --- |
| Available automatically for every existing Application | Created when a Creator deploys the Application for the first time |
| Used to build, configure, and test changes | Provides <L>Consumers</L> with a stable version |
| Continues using the existing Application URL | Has a separate URL to share with Consumers |
| Can continue changing as Creators work | Changes only when a Creator deploys an update |

When deciding which Applications to deploy to Production, we recommend starting with stable Applications that Consumers rely on regularly. Other Applications can remain in Development until they are ready.

<Admonition title="Two Things to Know Before You Deploy">

* **Next-Gen only.** Development and Production apply to Applications in Next-Gen mode. Applications in Classic mode are not affected.
* **One-way switch.** Deploying an Application to Production locks it to Next-Gen mode permanently. You can no longer switch it back to Classic mode.

</Admonition>

**Build, inspect, and deploy**

* **Build:** Creators configure the Application in <L>Edit Mode, then switch to User Mode</L> to preview what Consumers will see.
* **Inspect:** Happens automatically when a Creator clicks Deploy. Meridian Studio runs <L>pre-deployment checks</L> and stops the deployment if it finds a critical issue, so nothing blocking reaches Production.
* **Deploy:** The <L>Deployment Panel</L> creates the Production version and, after the first deployment, publishes subsequent changes.

**Find Development and Production Applications**

The **Applications** page shows Development Applications by default. Use the <L>**Deployment Status**</L> filter to view Applications that have been deployed to Production.

<img src="/img/release/applications-page.png" alt="Applications page with Deployment Status set to Development" loading="lazy" />

**What Consumers experience**

Consumers can continue accessing an Application through its existing Development URL until you are ready to move them to Production. After the first deployment, <L>share the new Production URL</L> with them.

New to all this? The <L>Development and Production FAQs</L> answer the questions we hear most.

<ReleaseCard id="rn-pivot" category="Next-Gen Applications" tag="Enhancement" title="No Row, No Edit: Pivot Cells Now Follow the Source Table" teaser="Pivot cells without a matching row in the source table are now disabled, so every edit saves to a real row.">

A Pivot shows a cell for every combination of the fields in **Rows** and **Columns**, whether or not that combination exists in your data. That's great for layout, but it made every cell look editable, even the ones with nothing behind them.

Now the source table has the final say. You can edit a cell only if the source table already has a row for that exact combination. If there's no row, the cell is disabled, so no typing and no pasting.

**Example:** A Pivot on the Demand Forecast table has product in **Rows**, location in **Columns**, and `forecast_qty` in **Values**. Product P003 has rows only for L002 and L004.

| product | L001 | L002 | L003 | L004 |
| --- | --- | --- | --- | --- |
| P003 | Disabled (no row) | Editable | Disabled (no row) | Editable |

<ReleaseClip src="/img/release/pivot-cells.mp4" alt="A Pivot where cells without a source row are disabled and cells with a row can be edited" />

Need to edit a disabled cell? <L>Which Pivot Cells Are Editable</L> shows you how.

</ReleaseCard>

<ReleaseCard id="rn-blocked" category="Next-Gen Applications" tag="Enhancement" title="Blocked Actions Finally Explain Themselves" teaser="When Save, Reset, Scenario creation, or an Action run is blocked, the error now names the reason and the fix.">

**Save unavailable, the Data configuration needs to be updated before the data can be saved.** No reason, no next step. So you clicked **Update Changes** until you gave up and called support.

Now, when your Application's tables no longer match the Semantic Layer, **Save**, **Reset**, Scenario creation, and Action runs are blocked with an error that names the reason and the fix:

| Reason | How to fix it |
| --- | --- |
| **Table schemas changed:** A column in the Sequence was added, removed, or changed type. | Click **Update Changes** in the Semantic Layer. |
| **Tables were deleted:** A table the Application uses was deleted from the Sequence. | Click **Update Changes** in the Semantic Layer. |
| **Tables aren't Storage Class 2:** A table the Application uses is Live or Storage Class 1. | Convert it to Storage Class 2 in the Sequence. |

Several reasons at once? Each gets its own bullet in the same notification.

</ReleaseCard>

<ReleaseCard id="rn-predict-demand" category="Science Notes" tag="New Feature" title="Predict Demand - Version 1.5.0" teaser="Adds Telescopic Modelling: XGBoost forecasts the validated near term, and a stable continuation covers the rest.">

The <L>Predict Demand</L> Note trains on prepared data and produces the final forecast through experimentation, training, and prediction.

This release adds Telescopic Modelling, which trains the Global Model only up to the Model Selection Horizon and extends the rest of the forecast with a naive continuation. Runs finish faster, and extended rows are marked `forecast_source = telescopic_tail` in the output.

<Expandables>
<ExpandableItem title="Expand for details">

**What's New**

* **Telescopic Modelling**: With Telescopic Modelling on, XGBoost forecasts only up to the Model Selection Horizon, and a blended naive continuation (seasonal pattern plus recent level) forecasts the rest. The continuation starts from the champion's own near-term forecast, so the two segments join smoothly. For example, with a Forecast Horizon of 24 and a Model Selection Horizon of `0,1,2,3,4,5`, XGBoost forecasts periods 1 to 6 and the continuation forecasts periods 7 to 24.
* **Turning it on**: In Prepare Demand, go to **Parameters &gt; Prepare Time Series**, set Model Selection Horizon to fewer steps than Forecast Horizon, and turn on **Run Telescopic Model**. Off by default.

**Limitations**

* Applies to Global (XGBoost) champions only. Local / Statistical and Foundation forecasts are unchanged.
* Can't be used together with Quantile Forecast. A run with both turned on is rejected before it starts.

</ExpandableItem>
</Expandables>

<ReleaseCard id="rn-optimize-network" category="Science Notes" tag="Enhancement" title="Optimize Network - Version 4.3.0" teaser="Four Note Actions replace the single run, and two mid-run Controls let you check the best plan or stop the search early.">

This release changes how you run the Note. Four Note Actions replace the single run, so you can stop after checking your data, after checking the model, or go all the way to a plan, and a full optimization now exposes two mid-run Controls that let you read the current best plan and end the search without losing it.

<Expandables>
<ExpandableItem title="Expand for details">

**What's New**

* **Note Actions.** Four named ways to run the Note: **Validate Data**, **Validate Model**, **Run Full Optimization** (the default), and **Solve with Decomposition**.
* **Controls: Fetch KPIs and Stop Solve.** During **Model Solve**, **Fetch KPIs** publishes 17 KPIs of the best solution found so far to a new **Live KPIs** panel, and **Stop Solve** ends the search, keeps that solution, and continues to Report Generation.

**Required Steps When Upgrading**

| What changed | What to do |
| --- | --- |
| **Model Decomposition runs only under Solve with Decomposition.** Under Run Full Optimization the `Model Decomposition` parameter is ignored and the monolithic model is solved | Select **Solve with Decomposition** for runs that should decompose, and keep the strategy set in the parameter |

</ExpandableItem>
</Expandables>
